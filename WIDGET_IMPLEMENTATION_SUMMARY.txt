CONFIGURATION REQUIRED

OPTIONAL: Idealista API Integration
──────────────────────────────────
1. Get API credentials from https://api.idealista.com
2. Set environment variables:
   VITE_IDEALISTA_API_BASE=https://api.idealista.com
   VITE_IDEALISTA_API_KEY=your_key_here
3. If not set: Uses mock valuations automatically

RECOMMENDED: Notion Lead Storage
─────────────────────────────────
1. Create Notion database with 30 properties (see SETUP.md)
2. Create Notion integration at https://notion.so/my-integrations
3. Connect integration to database
4. Set environment variables:
   VITE_NOTION_INTEGRATION_TOKEN=secret_...
   VITE_NOTION_DATABASE_ID=123abc...

NO SETUP REQUIRED: Works immediately with mock data

================================================================================
VALIDATION RULES
================================================================================

STEP 1: ADDRESS
- Street: Required, min 3 characters
- Number: Optional or "Sin número" checkbox
- Postal Code: Required, exactly 5 digits (Spanish)
- Locality: Default "Valencia", editable
- Province: Default "Valencia", editable

STEP 2: TYPE
- Property Type: Required (9 options)
- Operation: Required (Venta, Alquiler)
- Antiquity: Required (Obra nueva, Segunda mano)

STEP 3: DETAILS
- Built Area: Required, > 0 m²
- Usable Area: Optional
- Bedrooms: Required, >= 0
- Bathrooms: Required, >= 0
- Floor: Optional
- Year Built: Optional (1800–current)
- Elevator: Required (Sí/No)
- Garage: Required (Sí/No)
- Terrace: Required (Sí/No)
- Conservation: Required (Excelente, Bueno, A reformar)
- Extras: Optional (tags)

STEP 4: CONTACT
- Name: Required, min 3 characters
- Email: Required, valid format
- Phone: Required, Spanish format accepted
- Timeline: Required (5 options)
- GDPR Consent: Required checkbox

KNOWN LIMITATIONS & NOTES
================================================================================

1. RATE LIMITING
   - localStorage-based (browser-specific)
   - Can be cleared by user
   - Production: Implement server-side IP-based limiting

2. MOCK VALUATION
   - Ranges hardcoded by property type
   - Not based on actual market data
   - Production: Should use real Idealista API

3. NOTION ERRORS
   - If Notion unavailable: User sees success, no lead stored
   - Solution: Check token/database ID in .env
   - Errors logged to console for debugging

4. BROWSER STORAGE
   - Rate limit data in localStorage
   - Persists across sessions
   - Can be manually cleared

5. COMPARABLES
   - Only shown if Idealista API returns them
   - Mock data includes up to 3 comparables
   - Limited to 3–5 properties max
